# Contributing

Use Node >=22.19 and `npm ci`. Run `npm run check` and `npm run format:check` before submitting changes. Keep package-lock.json in sync. Never include API keys, auth.token, local state/workspaces or private chat data.

Keep DSH integration in the adapter module. A new Desktop release requires pinned-source verification, exact-package typechecking, real Loader/AgentLoop tests, permission/cancellation tests, and a user-run signed-Desktop acceptance test. Do not remove version checks, copy internal Host credentials or add implicit CLI/Web fallback.

New tools need explicit authorization semantics, resource bounds, a teardown path, negative tests and bilingual documentation. All mutations must state uncertain-response handling. No test should require a paid model key by default. Preserve task workspaces and user changes.

Releases are prepared manually; CI does not publish. See [RELEASING](docs/RELEASING.md) for the release process.

Codex plugin payloads under plugins/dsh-desktop/runtime and its Desktop archive are generated by npm run package:plugin and intentionally distributable through Git marketplaces. Preserve THIRD_PARTY_NOTICES.txt, validate plugin manifests and test the relocated bundle without node_modules.

Run `npm run test:compatibility` before changing the supported version matrix. It installs exact dependencies and runs strict typechecking plus the complete suite in separate temporary directories for each supported Desktop version. It never edits the user Desktop profile or starts a Harness CLI/Web runtime.

Run `npm run verify:npm -- --package ./outputs/dsh-desktop-mcp-bridge-0.2.1-rc2.tgz` after packaging to check installation into an empty consumer project, CLI registration, MCP initialization and private configuration setup. Omitting `--package` installs the exact current version from the public registry with a fresh anonymous cache. `--desktop-config` adds a connection check; `--live-task` additionally makes bounded real model calls and tests session follow-ups/cancellation.
